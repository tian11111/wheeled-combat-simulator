# Godot 桌面端 UI 优化

## Goal

提升 Godot 桌面端在比赛实况、回放和布局编辑时的信息可读性与操作效率，让用户能快速识别比分/阶段/双方状态，并明确当前可用操作；不改变仿真规则、回放协议或布局数据语义。

## Confirmed Facts

- 当前 HUD 由 `godot/src/HudPanel.cs` 程序化创建，包含左上状态、左下事件、右上帮助、底部回放条和顶部编辑栏。
- 当前控件主要使用固定偏移、基础 `Label`、`Button` 和 `PanelContainer`，窗口缩放下的信息层级和密度仍有优化空间。
- `godot/src/Main.cs` 负责会话/命令路由，`godot/src/LayoutEditor.cs` 负责编辑逻辑；UI 改造不得把规则或布局权威移入 Godot UI。
- 当前真实窗口 renderer 冒烟已通过，截图证据为 1152×648；headless dummy renderer 不能作为视觉截图证据。

## Scope

### In Scope

- 比赛 HUD：阶段、剩余时间、比分、重启判罚、双方状态和最近事件的视觉层级、颜色和卡片布局。
- 编辑工具栏：选中对象、检视值、状态提示、应用/撤销/重做/恢复/打开/另存/退出按钮的分组、间距和状态反馈。
- 回放控制条：播放/暂停、首尾帧、单步、tick 和时间轴的可读性。
- 1280×720、1920×1080 及当前窗口尺寸下的锚点/缩放适配和截图 QA。

### Out of Scope

- 不修改 `Sim.Core`、`Snapshot`、回放指纹、判分逻辑或布局数据格式。
- 不重做场地、机器人模型或最终美术资产。
- 不增加新的比赛功能、遥测功能或在线服务。

## Requirements

- R1：状态信息按“比赛阶段/时间/比分/双方状态/事件”分层，关键状态不再依赖一整块等权重纯文本。
- R2：我方/对手、运行/暂停/结束、可应用/不可应用等状态有稳定且可辨识的颜色与文字表达，不能只依赖颜色。
- R3：编辑栏和回放栏保持现有快捷键与回调顺序不变，按钮禁用态和当前模式清晰可见。
- R4：控件使用锚点和容器布局适配窗口尺寸，不遮挡关键场地视野；动态文本变长时不能导致控件重叠或截断关键值。
- R5：视觉改造只消费现有 `RenderFrame`、会话模式和编辑器状态；所有规则结果与 parity 行为保持不变。

## Acceptance Criteria

- [x] 真实 renderer 下实况、回放、编辑模式各至少有一张可复核截图：`live-1280.png`、`replay-1280.png`、`edit-mode.png`，截图均包含场地和新的 UI 层级。
- [x] 1280×720 和 1920×1080 窗口下无明显重叠、关键文本未截断；`replay-1280.png` 与 `replay-1920.png` 已复核回放条、事件卡和操作区间距。
- [x] 现有编辑器 22 项逻辑冒烟、Godot parity（2400/2400）、CLI replay-check（752/752）和全量 .NET 测试（189/189）通过。
- [x] 产品 diff 只包含 `godot/src/HudPanel.cs`；未改变 `Sim.Core`、回放文件、场景布局协议和渲染/仿真边界。

## Key Decisions

- 用户已确认采用“深色赛事控制台”视觉方向：深色半透明卡片、冷色信息、黄/蓝双方强调、红色警告。
- MVP 先优化 HUD、编辑工具栏和回放控制条，不重做场地和机器人美术，不增加新的比赛功能。
- 所有 UI 状态继续由现有 `RenderFrame`、会话模式和编辑器状态驱动；不在 UI 层复制规则或布局真值。

## Risks and Deferred Items

- 中文字体、动态事件文本和小窗口宽度可能造成截断；通过容器布局、最小尺寸和 1152/1280/1920 宽度截图回归处理。
- 不引入第三方图标包或新的美术资产；先沿用现有文字/符号控件，图标系统留到后续需求。
