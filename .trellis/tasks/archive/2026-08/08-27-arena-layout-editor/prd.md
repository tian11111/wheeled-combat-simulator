# 按图纸校准场地与桌面布局编辑器

## Goal

让桌面模拟器的场地几何与 2026 轮式格斗规则图纸一致，并支持在 Godot 中编辑场地布局、导入机器人外观模型，使编辑结果能够被仿真内核和回放复用。

## Background And Confirmed Facts

- 规则 PDF `D:/project/robocup/1779761830740288.pdf` 规定：外场内尺寸 3.8m × 3.8m；中心擂台 2.4m × 2.4m、高 6cm；擂台四周黑色地面宽 70cm；外围方形黑色围栏高 20cm；黄、蓝出发区各 50cm × 40cm，距擂台边缘 20cm；场上随机放置 2 个增益块和 1 个减益块，能量块尺寸 15cm 见方。
- 当前 [ArenaVisualizer.cs](D:/project/robot-simulator/godot/src/ArenaVisualizer.cs) 使用固定常量绘制场地，缺少黄/蓝出发区、“武”字和真实灰度渐变；围栏视觉高度也与规则不符。
- 当前 [FieldModel.cs](D:/project/robot-simulator/src/Sim.Core/FieldModel.cs) 只支持轴对齐的方形擂台，仿真判定使用固定平台边界；Godot 端没有场地移动/旋转/编辑入口。
- 机器人外观当前由 Godot primitive mesh 程序化生成。现有仿真协议中的 `VehicleProfile` 负责尺寸、碰撞半径和铲子等判定参数，外观模型不应改变这些权威参数。

## Requirements

### R1. 图纸一致的场地表达

将外场、擂台、6cm 台阶、70cm 黑色走道、20cm 围栏、灰度渐变、中心红色“武”字区域和黄/蓝出发区表达为同一份可序列化场景数据。默认官方场景必须保留 3.8m × 3.8m、2.4m × 2.4m、0.06m、0.70m、0.20m、0.50m × 0.40m、0.20m 间距等尺寸。

### R2. 仿真与显示共用几何

登台、掉台、围栏边界、机器人出生区和能量块初始位置必须从场景数据读取；Godot 不能只移动画面而不改变 `Sim.Core` 的判定几何。现有回放协议保持向后兼容，旧场景缺少新增字段时使用官方默认值。

### R3. 桌面布局编辑

Godot 桌面端提供独立编辑模式，可选择场地整体、出发区或能量块；场地整体支持平移和绕竖直轴旋转，出发区和能量块支持在场地局部坐标内拖动。编辑器支持网格吸附、撤销、重做和恢复官方布局，并能退出编辑模式回到比赛模式。编辑操作应有明确的选中状态、变换数值和可见反馈；比赛运行或回放播放期间不得直接改变布局。

### R4. 场景保存与复用

编辑后的布局可导出为 JSON 场景文件，并能从文件重新加载；CLI、Godot 实况和回放加载同一文件时使用相同几何。该能力是 MVP 必选。保存格式需使用新增 `layoutVersion` 和增量字段演进，不能破坏现有 `Scenario` / replay-v1 文件。

### R5. 机器人模型导入

Godot 支持从项目资源或用户选择的文件加载 `.glb` / `.gltf` 机器人外观模型；每个阵营可配置独立模型，加载失败或未配置时回退到当前 primitive 模型。模型应能随快照位置、朝向、登台高度更新。

### R6. 权威边界与安全约束

导入模型只影响渲染，不参与碰撞、计分或登台判定；权威碰撞尺寸、质量、轮距、铲子和传感器继续来自 `VehicleProfile`。编辑器不得引入 Godot/Jolt 作为新的判分物理源。

## Acceptance Criteria

- [x] 默认场景渲染出与规则尺寸对应的外场、2.4m 擂台、6cm 台阶、70cm 黑色走道、20cm 围栏、黄蓝出发区和中心“武”字/灰度渐变，并有自动化尺寸回归断言。
- [x] 同一份场景 JSON 被 CLI 与 Godot 加载时，平台边界、出发区和能量块坐标一致；旧版官方场景仍能通过现有 95 项回归测试。
- [x] Godot 编辑模式可完成选择、拖动、旋转、吸附、撤销/恢复默认，并且编辑后退出编辑模式不会影响普通比赛控制。
- [x] 场地整体平移/旋转后，机器人出生位置、平台/围栏碰撞、登台/掉台和渲染使用同一坐标变换；比赛运行或回放期间编辑操作被禁用。
- [x] 编辑布局可保存、重新加载，并通过一次 CLI 比赛和一次 Godot 载入验证几何一致。
- [x] `.glb/.gltf` 模型可加载并跟随机器人快照移动；缺失/损坏模型会回退 primitive，且仿真结果不变。
- [x] `dotnet test`、Godot headless 加载、场景尺寸检查、回放 parity-check 和桌面交互冒烟全部通过。

## Out Of Scope

- 不在本任务内实现真实轮胎/电机/悬挂动力学或用 Godot/Jolt 替换 `Sim.Core` 权威物理。
- 不制作最终美术资产；只提供导入接口、占位模型和必要的材质/缩放适配。
- 不新增数据库、微服务或联网多人功能。
- 不支持 FBX/OBJ 等运行时转换；MVP 的外部模型格式为 `.glb/.gltf`。
- 不在本任务内实现通用关卡编辑器、任意多边形擂台或多个擂台。

## Key Product Decisions

- 编辑后的场景 JSON 保存、重新加载并直接驱动 CLI/Godot 仿真是 MVP 必选能力。
- 场地移动指场地整体在仿真世界中的平移与绕竖直轴旋转，不只是移动相机或视觉节点。
- 机器人外观模型与权威 `VehicleProfile` 完全解耦；模型导入不得改变比赛结果。
