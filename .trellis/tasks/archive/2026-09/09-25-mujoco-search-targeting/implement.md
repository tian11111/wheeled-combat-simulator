1. [ ] **冻结输入与复现基线（AC1）**：记录 `git rev-parse HEAD`、`git status --short`、`dotnet --info`、MuJoCo 原生版本、场景文件哈希。建立 `$qaDir = Join-Path $env:TEMP 'robot-simulator-mujoco-search-targeting'`，运行 `New-Item -ItemType Directory -Force -Path $qaDir`。用 `dotnet run --project src/Sim.Cli -- match --seed 42 --scenario scenarios/wushu-ring-2026-mujoco.json --events` 跑默认 120 s，并以 `dotnet run --project src/Sim.Cli -- match --seed 42 --scenario scenarios/wushu-ring-2026.json --events` 做 legacy 对照；分别保存完整 stdout/stderr、退出码、比分与事件顺序。不要把历史 60 s/短 batch 结果写成当前基线。
2. [ ] **逐 tick 定位首个卡点（AC1）**：在 `src/Sim.Tests/MujocoIntegrationTests.cs` 增加临时诊断入口或使用一次性诊断程序，使用 `MatchEngineHost.Create`、`Arm()`、`Tick()` 和公开运行态读取；保存 tick、build/profile/range、角色、通道、原始/逻辑红外、`Probe.D/Obj`、目标坐标、`Fsm.State/Scan.Phase/T`、`V/W/CmdV/CmdW`、车体 `X/Y/Th/Omega`、相邻位姿算出的 yaw rate、`OnPlatform`、块位置和事件。将读到的 probe 解释为本 tick 物理步进前的采样，避免一帧错位。查首次发现至目标丢失的 3 s 窗口；若当前默认对角探针出现原始 `D>1.6 m` 或目标身份不一致，先修正该数据契约与对应测试，再重新取得基线；若根因不是转向不足，停止步骤 3 的补偿方案并回写设计。
3. [ ] **受控转向对照（AC2）**：在现有 `MujocoIntegrationTests` 中构造台面中心我方 `(1.9,1.9,0)`、相对 `3π/4` 方向 0.8 m 处唯一可见目标的场景，令我方真实进入 SEARCH，静止对手以零动作保持；不要直接写 `Scan.Target`。先用原映射系数 1 保存轨迹，然后仅在 `SetControls` 原地转向分支试 2、4、6，保留现有轮速截断、轮力、`kv` 与摩擦。每个候选重跑定向测试及 `NativeMode_FsmMountsFromOfficialSpawn`；比较首次发现到 classify 的时间、末端误差、偏航率、车体位移、RECOVER/掉台和轮速饱和。选满足 `<3.0 s`、`<0.15 rad`、登台不回归的最小候选。全部失败时撤销实验补偿、保留每组轨迹与失败 tick，回到设计，不进入下一步。
4. [ ] **完整行为测试（AC3）**：沿用步骤 3 的受控布置分别放一个 buff 与静止 opponent；buff 场景只把目标作为可见方块，对手离开探针范围；opponent 场景不要让其他方块先被探针命中。断言真实发现、classify、正确分流；继续运行至 buff 发生接触、位移和 `BlockScore`，opponent 发生追击/`Contact`。保留首次状态转移、首次接触和得分 tick，新增负例证明 debuff 不走 `SCORE_BLOCK`。若对准达标但得分失败，定位 `ScoreTick`/接触/裁判中的首个失败阶段，保持 AC3 失败并回到设计，不通过放宽 SEARCH 门槛制造进展。
