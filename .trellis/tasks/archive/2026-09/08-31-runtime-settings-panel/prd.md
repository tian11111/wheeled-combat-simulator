# 设置界面与运行参数配置

## Goal

为 Godot 桌面端增加可返回的设置界面，让用户能配置显示/窗口选项以及受控的下一场仿真参数，并以持久化配置安全地恢复。

## Confirmed Baseline

- 主场景目前只有 `CanvasLayer/HudPanel`，`Main` 在 `godot/src/Main.cs:59-197` 组装会话、视觉和现有文件对话框，没有独立设置状态或配置服务。
- `godot/project.godot:19-27` 已声明 1280×720 设计视口、可调整窗口和 CanvasItem 拉伸；实际分辨率/全屏设置应走 Godot `Window`/`DisplayServer` 的桌面壳能力。
- `Scenario` 的可复现输入包括 `Field`、`Vehicles`、`Blocks`、`Parameters`；`SimParameters` 已有明确键名和部分单位，但未知键会被拒绝。
- 布局编辑器和回放规范要求编辑/设置不能触碰运行中的权威引擎；应用新的仿真参数应重建新会话。

## Requirements

- R1：提供设置打开/关闭、分组、取消/应用/恢复默认和错误提示；关闭设置后回到原模式且不丢比赛/回放上下文。
- R2：至少提供分辨率、窗口化/全屏和 UI 可读性/缩放配置；显示配置即时应用或明确提示重启/下次启动生效。
- R3：提供经过白名单、范围、单位和精度校验的下一场仿真参数编辑；比赛运行或回放播放中不得直接改变当前引擎。
- R4：将桌面偏好与场景参数分开持久化；配置损坏、缺字段或版本未知时回退默认并给出诊断，不污染官方场景、回放和 fidelity。
- R5：设置校验、持久化、恢复默认、应用边界和旧配置兼容有自动化覆盖，Godot parity/回放/布局编辑行为不回归。

## Acceptance Criteria

- [ ] 用户可在界面内改变并验证支持的分辨率/全屏设置，应用后画面与玻璃 HUD 同步缩放。
- [ ] 非法输入不会改变当前设置或比赛；重启应用后合法持久化值可恢复，损坏配置安全回退。
- [ ] 下一场参数应用后新 Scenario/MatchSession 使用它；当前进行中的比赛、回放和旧回放指纹保持不变。

## Key Decision

- 已确认：显示/窗口设置即时应用；仿真参数和控制器配置只在新比赛或显式重置后应用，不修改正在运行的 `MatchEngine` 或当前回放。
- 已确认：现有 `SimParameters` 的全部已登记键进入白名单，按“常用/高级”分组，带单位、默认值、范围和实验性提示；不新增内部常量。
