# 设计：SCORE_BLOCK v3 修复后重训

## 边界与数据流

第一阶段直接复用现有 `train.py`、`evaluate.py`、`ScoreBlockEnv` 和 split v3，不修改环境。用当前已修复的 CLI DLL 训练无防护模型，按 checkpoint + 最终模型在 7001–7020 选模。若它合格，冻结并进入一次 8001–8050 盲验，不添加第二种机制。

只有第一阶段开发集无合格模型时，第二阶段才在 Python `ScoreBlockEnv` 动作出口加入 `safety_mode=target_edge_speed_cap_v1`。每次 reset/step 保存的 info 描述下一动作的当前状态。`step(action)` 先按原契约裁剪 Box 动作，再读取 `target_edge_distance`（米）；距离 `< 0.45` 且正向 v `> 0.35` 时仅把送往 JSONL 的 v 改成 0.35。w 保持 `2*action[1]`，倒车不改。当前阶段 info 缺失/非有限距离时启用模式应报错，避免暗中退回无防护。每集累计触发 tick，在返回 info 中给出原始/实际 v 与本步触发标志；不修改桥协议或 C#。

训练脚本只增加显式 `--safety-mode` 选择，在 `run-config.json` 记录模式、阈值、上限和触发次数日志字段。评测脚本使用同一模式，从相邻训练配置核对模型与模式，输出模式与逐集触发量；冻结记录和 `--require-freeze` 校验同时包含模式。`none` 保持现有动作行为和旧模型的历史分析能力。此限速使用仿真真值距离，是 PPO + 确定性安全层候选，不声称只靠神经网络或可直接真机部署。

## 选模与盲验

开发集只使用 7001–7020。沿用真实裁判门槛与排序；FSM 每 seed 从相同首次 `SCORE_BLOCK` 入口评测。若无防护模型有合格候选，就不启用限速实验。否则评测限速模型的全部 checkpoint + 最终模型。冻结唯一合格候选与代码/模型哈希后，8001–8050 只运行一次，写新文件且不覆盖。盲验失败则停止，下一次算法修改另建 split；本轮不能用 `--force` 重判。

## 回退与兼容

Python 模式默认 `none`，现有外部控制器、默认 FSM 与旧回放行为不变。限速层不进入 `Sim.Core`；桥错误、缺失距离或训练中断时明确失败，保留配置/日志，不产生通过结论。无防护与限速模型输出目录分开，避免 checkpoint 混用；大型权重留在 Git 忽略的 `.sim_runs`，任务证据只入库小型摘要和逐 seed 结果。
