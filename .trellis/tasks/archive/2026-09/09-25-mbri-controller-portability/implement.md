# 实施清单：MBri 控制器接入契约

> 规划阶段；不因用户已跑通一场就把适配结果视为物理或感知验收通过。先复现用户命令并保存证据，随后按 PRD 的 AC 逐项验证。

1. [x] 固定基线：保存当前 MBri `sim_bridge.py` 的 60 秒命令、stdout/stderr、`--events`、fault、比分、场景/提交标识；单独记录外部角色事件分类，复核 Arm 与裁判是否真缺失。
2. [x] 写 `docs/CONTROLLER_PROTOCOL.md` 移植章节与映射表；把当前官方场景 `Legacy14`、可选 `WheeledCombat11` 和 MBri 六路 GPIO 的差异写准，附安全标定表模板和完整运行命令。
3. [x] 做最小 MBri 示例适配器及固定 Observation 夹具：显式运动系数/轮距/感知模式，输入校验、`obs.t` 时间注入、左右轮映射、request-id、stderr 元数据。保持底层 JSONL 协议不变，近似 IR/oracle 视觉不得默认开启。
4. [x] 先用定向测试核对每个量纲与失败分支，再做 60 秒真实 MBri smoke；保存逐帧 fault 和车端状态摘要，不以比分作为协议通过条件。
5. [x] 验证 Manual 语义和事件归属：固定可触发裁判事件的场景/seed，比较外部/内置角色；若裁判事件实际丢失，仅修复投影/输出，记录旧回放与同动作规则结果是否逐位不变。
6. [x] 运行现有 .NET 测试及外部控制器协议/回放回归，记录命令、版本、通过数和未标定边界；审阅 `.trellis/spec/sim/index.md` 与 backend 指南，必要时沉淀已验证契约。提交前检查只改计划列出的文件。

主要风险与回退：电机比例是车体相关的实测量，不能从 `START_REVERSE_SPEED` 猜出；接口不兼容时退回显式失败而非静默合成。若事件修复影响旧记录，回退事件投影变更，保留文档澄清与独立诊断日志。
