# SCORE_BLOCK 失败原因诊断：掉台与块出界归属

## Goal

在不改动 `Sim.Core` 物理/裁判/计分语义、不重新训练、不重跑门槛的前提下，用逐 seed 轨迹证据定位
MuJoCo `SCORE_BLOCK` 试点两轮盲验失败的两个缺口——**我方掉台次数高于 FSM 基线**、**锁定目标
"出界但未获得我方归属得分"**——并把结论收敛为一个**明确、可验证、单一**的候选修复方向。

本任务是诊断任务：产出证据与结论，**不实施修复**。修复与新一轮 split 预注册由后续独立任务承接。

## Confirmed Baseline（已核对的既有事实）

- 第一轮（`09-25-mujoco-score-rl-pilot`，已于 2026-09-26 按 AC4 失败结案归档）：4001–4010 上策略
  锁定目标真实 `BlockScore` 1、我方 `Drop` 8；FSM 0 / 7 → 门槛失败。
- 第二轮（`09-26-score-block-ppo-checkpoint-round`，已归档）：6001–6050 单次盲验上策略得分 5、
  掉台 28、锁定目标无归属 `BlockOff` 5（任意块无归属 `BlockOff` 10）；FSM 得分 8、掉台 21、
  无归属 `BlockOff` 0（任意块 1）→ `new_round_blind_gate_passed=false`。
- 训练日志显示策略从"开局很快掉台"变为"能撑到时限"，但掉台绝对数未随训练步数单调下降；
  开发集上的得分优势没有迁移到盲验集。**据此不能声称"再加训练步数"能补齐这两个缺口。**
- 计分规则（`Sim.Core`）：增益块离开擂台时，只有当 `BlockRuntime.LastContactRole` 恰好等于单一
  角色（`us`/`them`）才给该方 +3；`"simultaneous"` 与 `null` 都记为 `BlockOff` 且**不计分**
  （`src/Sim.Core/MatchEngine.cs` `ObjFallCheckAll`）。
- 归属来源：`PhysicsWorld.FinalizeBlockContacts` 取本 tick 内**接触时刻最大**的记录集，
  `last.Count == 1` 才取该记录的角色，否则判 `"simultaneous"`（`src/Sim.Core/Physics.cs`）。
- MuJoCo 后端每个裁判 tick 跑 `SubstepsPerTick = 10` 个子步（`SubstepSeconds = 0.005`），
  并把**每一个接触点**（不做几何对去重）按 `(role, contactTime)` 记入 `ContactThisStep`；
  单台机器人拥有多个几何体（`src/Sim.Mujoco/MujocoPhysicsBackend.cs`）。
  即：单台机器人在同一子步产生 ≥2 条同角色接触记录时，会被判成 `"simultaneous"` → 不计分。
- FSM 在 MuJoCo `SCORE_BLOCK` 中有显式防掉台与减速纪律，策略侧没有对应机制：
  `DistToNearestEdge(robot) < 0.27 && block 更靠边` → 倒车/回中（`ReturnFromMujocoScoreEdge`）；
  目标块距台沿 `< 0.45 m` 时把推进速度从 0.9 降到 0.35；对手更近时让出目标；无进展超时切目标
  （`src/Sim.Core/Fsm.cs` `ScoreTick`）。
- 奖励中的 `EdgeShapingScale` 作用对象是**目标块**到台沿的距离，对我方车辆靠近台沿**没有任何惩罚**；
  掉台一次性 −1.0（`RlEnvCommand` 常量）。

## Requirements

### R1. 逐 seed 轨迹证据（诊断的量）

对同 seed 配对的「策略」与「内置 FSM 基线」两条路径，逐 tick 记录并留档以下四类量：

1. **动作**：本 tick 施加给我方的 `(v, w)`（FSM 路径记为 none）。
2. **车与台沿距离**：我方与对手的位置/朝向/速度、`Field.DistToNearestEdge`、裁判口径的 on-stage 标志。
3. **块接触**：锁定目标块的位置/速度/`Out`/`WasOn`/`LastContactRole`、本 tick 的原始接触记录集合
   （角色 + 接触时刻），以及全部能量块的位置与出界状态。
4. **裁判事件**：本 tick 新增的结构化事件（`seq`/`kind`/角色/neutral/块名/原因），含 `Drop`、
   `BlockScore`、`BlockOff`、`Mount`、重启判罚等。

覆盖范围至少包含：6001–6050（已揭示，仅作分析）的策略 + FSM 配对，以及 4001–4010 的策略 + FSM 配对
作为跨轮对照。5001–5020 等开发集可用于交叉核对，但不得作为门槛证据。

### R2. 掉台原因定位

- 对每一次我方 `Drop` 事件给出可核对事实：掉台 tick、掉台前若干 tick 的位置与到台沿距离轨迹、
  当时的命令与速度、是否处于目标块接触/推块过程、是否伴随对手接触。
- 形成**掉台原因分类计数**（例如：推块贴边未减速、近沿仍全速/大转角、被对手顶出、
  追块越界、其他），并给出与 FSM 基线的同口径对照。
- 必须区分"策略指令导致"与"对手/物理导致"，对无法归因的样本如实标为未定，不得强行分类。

### R3. "块出界但未归属得分"原因定位

- 对每一个目标块的 `BlockOff`（以及可获得的任意块无归属 `BlockOff`）给出：
  出界 tick、出界前的接触角色序列、以及由**原始接触记录**判定的原因分类：
  `no_valid_contact`（无任何机器人接触记录）vs `simultaneous`（接触记录判定为同时）。
- 对判为 `"simultaneous"` 的样本，必须用接触记录**独立核实**是真双方争抢，还是单台机器人
  （我方或对手）的多点/多几何接触被误判；核实需要对手车与目标块的距离作为旁证。
- 若确认存在单机器人多点接触被误判为 `"simultaneous"` 的情形，给出发生频次、涉及的块与
  seed 清单，并说明该误判对两轮盲验得分缺口的量化影响（不得夸大：只报可核对的次数）。

### R4. 单一候选修复收敛

- 基于 R2/R3 的证据，给出**一个**优先修复方向，附：它解释的缺口、预测的可观测变化、
  如何用已有评测指标验证、以及为什么其他候选被排在后面（含反向证据）。
- 明确该修复属于哪一类（`Sim.Core` 归属判定缺陷 / 奖励或观测缺口 / 策略行为缺口 / 评测口径），
  并说明它是否会影响既有回放与确定性契约。
- 若证据不足以支持任何单一修复，如实报告"证据不足"，并列出补齐证据所需的最小实验。

### R5. 纪律与安全边界

- **不修改** `Sim.Core` 的物理、裁判、计分语义；不修改 11 维观测定义与奖励常量；不启动训练；
  不改评测门槛；不把已揭示的 seed 集重新当作盲验；不触碰 `fidelity.json`。
- 允许的代码改动仅限**诊断可观测性**：`rl-env` 的**可选、显式开启**轨迹输出，以及新增诊断脚本。
  默认（未开启轨迹）时 `rl-env` 的输出必须与改动前**逐位一致**，训练/评测路径行为不变。
- 诊断脚本与报告不得包含敏感设备标识；大型模型与逐 tick 全量轨迹不入 Git，只提交聚合结论、
  代表性样本与哈希。

### R6. 可复现与回归

- 诊断必须可由仓库内脚本 + 文档化命令重跑，并记录场景/CLI DLL/模型/依赖的 SHA-256。
- 代码改动后必须通过：`dotnet build`、`dotnet test RobotSimulator.sln -m:1 --no-restore`、
  既有 `replays/*.json` 的 `replay-check`（逐位 PASS）、以及新增 trace 路径的默认关闭一致性检查。

## Out of Scope

- 奖励函数/观测维度再设计（本任务只给证据与建议，不改常量）。
- 超参搜索、SAC/MJX、多次独立训练、真机迁移、`fidelity.json` 晋升。
