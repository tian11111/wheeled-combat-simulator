# 设计：比赛主界面与设置页视觉优化

## 边界

- 只改 Godot 展示层；首选分别调整 `godot/src/HudPanel.cs` 和 `godot/src/SettingsPanel.cs`。不改 `Sim.Core`、协议、回放格式、控制器语义或用户设置结构。
- 保持现有 HUD 区域位置、设置页七个标签及操作顺序、现有快捷键与对话框流程；不引入新的产品功能或第三方依赖。

## 比赛 HUD

- 在既有布局/缩放实现内解决相对视口的四角定位；以实际可见逻辑视口与 UI 缩放共同计算安全边距，不牺牲用户设置的缩放效果。
- 同时检查事件、回放工具条与布局编辑工具条的锚点、最小尺寸和交叠；不改变按钮动作、输入绑定、事件内容或场地渲染。
- 对比分、时间和控制器长提示改善字号、层级及文字换行；按项目规范避免自动换行与 `ClipText=true` 的组合。

## 设置页

- 保留现有自适应对话框、外层/页内滚动、页签、原生文件对话框及各页生效时机；以较小的留白/字体/样式调整增加内容可视面积。
- 在现有主题工厂统一控件视觉状态及可见焦点；任何键盘焦点改动必须验证设置弹窗不会把输入误传给比赛，保留原有 Enter、Esc 和快捷键语义。
- 高对比文字与状态色沿用深蓝背景、蓝红阵营和黄绿语义；维持颜色加文字，不引入新的状态含义。与 HUD 协调的设计起点：主要文字 `#E8F0FA`、次要 `#B4C4D6`、蓝 `#67B6FF`、红 `#FF8A80`、黄 `#F5C55F`、绿 `#68DDB4`；具体色值以现有界面与真实渲染可读性为准。

## 兼容和风险

- 缩放布局必须按 Godot 可见逻辑视口而非直接假设物理窗口像素；卡片实际 minimum size、不同模式下内容与控件不能相互覆盖。
- `Label` 的 `AutowrapMode` 与 `ClipText=true` 不可同时用于多行提示；设置页既有 `AddNoteLabel`、选项 ID、共享原生对话框与双层滚动契约保持。
- 不覆盖任何既有历史图像或用户设置；临时真实渲染证据使用隔离用户目录与任务专属临时路径。
- 使用本机 portable .NET SDK 运行 Godot 时需设置 `DOTNET_ROOT`；实际运行及真实渲染的验证结果见 `report.md`。
