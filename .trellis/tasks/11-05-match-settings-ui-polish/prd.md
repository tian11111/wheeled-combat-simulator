# 比赛主界面与设置页视觉优化

## 目标

让备赛人员在比赛主界面更容易读懂比分、剩余时间、双方状态与控制器提示，并改善设置页在常用屏幕与 UI 缩放下的可读性和操作反馈。

## 已确认范围与约束

- 范围：Godot 比赛 HUD 和设置页；延续现有深色竞技风、蓝红阵营和黄绿语义。
- 保持现有核心功能、比赛和设置业务逻辑、信息架构、页签及主要操作流程；不改仿真/协议/裁判规则、快捷键语义或数据格式。
- 按项目现有窗口和 UI 缩放范围适配；重点验证 1280×720、1920×1080、1280×720 @ 1.4 和 640×360 @ 1.4。
- 以现有代码与真实渲染为准；优先解决可读性、缩放可达性和控件状态，其次才是装饰。保留已有设置页外层/页内滚动、原生文件对话框及生效时机。
- 不覆盖历史截图或清理无关工作区内容；不训练、不运行盲集、不修改比赛核心。

## 需求

1. 优化 HUD 的比分、计时、双方状态与控制器告警层级；长提示可阅读，主界面缩放不将关键 HUD 卡片挤出可视区域。
2. 优化设置页高缩放时内容、页脚和控件的视觉密度，保留页面、字段、按钮和原有业务语义；重要文案不被静默截断。
3. 在现有样式工厂中协调文字、边框、间距及普通/悬停/按下/焦点/禁用等状态；颜色不能作为区分状态的唯一依据，保留已有文本提示。
4. 使用最小必要实现；未确认的问题先实际复现，不以历史截图推断当前运行结果。

## 验收标准

- [x] 在真实渲染截图中，比赛 HUD 的比分、计时、双方状态、控制器提示和事件区可见；1280×720 @ 1.4 时关键卡片不越出可视区域。
- [x] 设置页各现有页签与页脚操作可到达；1280×720 @ 1.4 无页面/页脚裁切，640×360 @ 1.4 下可通过滚动访问内容。
- [x] 比赛、回放和编辑模式的关键 HUD 与已有按钮、提示及快捷键未被遮挡或误改；可用的鼠标/键盘反馈清楚，无键盘触发比赛动作的回归。
- [x] Godot 工程构建、相关自动验证与必要的回放/parity 验证通过；至少记录 1280×720 和 1920×1080 的真实渲染证据，并在最终说明中区分已执行与受环境阻挡的检查。
- [x] 变更保持在界面表现范围；记录尚未验证的交互、分辨率或环境限制。
