# 执行计划

1. 读取 split 守卫、吞吐及策略报告；逐项核对正向 Go、4/5 开发集门槛和 v4 最终集未揭示。任一不符即 No-Go，不触碰最终集。
2. 仅用开发集裁判事件按 design.md 固定排序选唯一候选；冻结模型/checkpoint、训练 seed、代码/场景/CLI/split/依赖/配置哈希和开发集证据。
3. 运行冻结验证、命名 split 路由、固定 seed 确定性、Gymnasium checker、Sim.Tests、旧回放；任何失败先修复并重新冻结，不能在已开最终集之后做这些准备工作。
4. 检查一次性运行登记和输出目录为空；仅对 `final_holdout_v4=10001–10050` 启动一次 deterministic PPO/FSM 配对评估。保留完整 stdout/stderr、每场原始裁判事件和故障记录。
5. 无论运行结果是否满足门槛，都将 v4 最终集标记为已揭示；不得换模型、调整门槛、用 `--force` 重判或将其重新声明为盲集。
6. 汇总 `BlockScore`、Drop、得分归因和 fault 四项门槛，写 `report.md` 的逐场表、运行身份、冻结/运行时间、Go/No-Go 和已揭示状态。运行中断或不完整也报告失败及已打开状态，不补跑冒充一次性盲验。
7. 父任务最终只按该报告判断策略目标；失败时保留负面结果，下一次改进须另设新 split。
