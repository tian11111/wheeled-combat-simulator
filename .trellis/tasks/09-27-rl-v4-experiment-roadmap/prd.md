# RL v4 实验路线与证据门控

## Goal

以真实得分和跨训练 seed 稳定性为主目标，先测吞吐瓶颈，再按证据决定提速与策略实验。此父任务只管理六项子任务的规划、顺序和最终集成验收；本轮不启动实现或训练。

## 已知基线

- v3 的一次 500k PPO 训练记录为 307.595 steps/s；这是单次历史观察，不是并行收益承诺。
- v3 一次性 50-seed 盲验：PPO 锁定目标真实 `BlockScore=2`，配对 FSM 为 6；我方 `Drop=25`，FSM 为 29。得分门槛失败，v3 盲集已揭示。
- 首项任务实施前，代码仍将 `final_holdout_v3` 注册为 blind；该缺口必须先修复为仅分析，并预注册 v4。

## 全局要求

- 每项子任务独立交付 `report.md`，明示前置报告、证据路径、Go/No-Go 和失败停止路线。证据任务可因可信负面结果完成；只有满足表中正向门槛才解锁需要正向结果的下游。
- 固定训练 RNG seed `20260927、20260928、20260929、20260930、20261001`。训练池、开发集、盲集和历史 split 不得重叠；开发集用于选模，最终集只用于一次验收。每个训练 seed 报告逐项结果，不以最佳 seed 代表稳定性。
- 选模与验收依据配对裁判事件中的锁定目标真实 `BlockScore`、我方 `Drop`、得分归因和 fault；reward 与 PPO loss 只用于诊断。冻结唯一模型和代码、场景、配置哈希后方可打开最终集。
- 先试五个独立 `n_envs=1` 训练；不达吞吐目标再试 `SubprocVecEnv`。只有重复测量显示 IPC/序列化至少占单步 25%、CPU 未饱和，才可试原生 .NET batch。
- 保持现有 11 维特权观测、reward v2、物理、FSM 和 PPO 参数作为原版基线。GPU/MJX、SAC、26 维观测、课程学习、真机部署不进入本轮。
- 任何前置 No-Go 都保持后续任务 `planning`；不得用后续任务的产物补写前置报告或复用已揭示盲集调参。
