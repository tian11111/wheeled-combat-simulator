# 设计：RL v4 递进实验

## 证据边界

v3 只有一个训练 RNG seed 和一次 50-seed 最终盲验。它证明该冻结候选的得分门槛失败，不能证明所有 PPO 配置失败，也不能给出跨训练 seed 稳定性。已打开的 `final_holdout_v3` 只能供分析。研究报告中的加速倍数、八周工期和原生 batch 收益均是预测，须由本机重复测量决定。

## 数据与门控

1. `split-guard` 维护 `splits.py` 的唯一注册源：v3 已揭示、v4 开发集和盲集预注册。评估入口把 `gate_evidence_eligible` 和 analysis-only 状态写入结果。
2. `baseline-profiling` 记录分阶段时延及 CPU/RSS，建立同机可复核的瓶颈报告。负面瓶颈结论仍可解锁提速证据任务，但不自动允许原生 batch。
3. `training-throughput` 先跑五个独立单环境进程，失败后才比较 `SubprocVecEnv`；仅符合 IPC≥25% 且 CPU 未饱和的条件才研究原生 batch。该任务必须达到 5×500k 中位总墙钟≤60 分钟，才可解锁策略实验。
4. `split-multiseed` 固定五个训练 RNG seed，使用原版 PPO、11 维观测、reward v2。按开发集 20 场的配对裁判事件逐模型判定。至少 4/5 达标时直接进入冻结。
5. `reward-credit` 仅当原版未达标时执行。接触归因规则先由轨迹确定，之后只修改边缘进展奖励，按 3→5 seed 两段门槛运行。
6. `blind-gate` 依据已预注册排序选唯一开发集候选，冻结模型和运行身份，再只运行一次 50 场最终集。结果失败即停止，不换模型、不调门槛。

父任务的孩子关系只表达交付分解；可运行性完全由各子任务 `report.md` 的 Go 条件决定。原版基线达标时，奖励任务在报告中记为“条件未触发”，不作为盲验前置。任何缺失/失败报告均按 No-Go 处理。

## 版本与可比性

训练产物记录代码、场景、配置、依赖、split 和模型哈希，训练 seed 与场次 seed 分开。若改动控制器观测、物理、规则或对手 FSM，开发集比较失去单变量解释力，应停止并重新规划。原生 batch 如被触发，独立 `mjData` 和 reset/终止语义必须与单环境轨迹对齐。

## 数据暴露

开发集可反复用于模型选择，但所有搜索范围和排名规则在打开 v4 最终集前固定。最终集只用于冻结候选一次性验收；首次运行后即标记已揭示。指标只从裁判事件取值，episode reward 和 PPO loss 不参与排名。
