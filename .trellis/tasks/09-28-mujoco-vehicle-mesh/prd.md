# MuJoCo 物理车体改用真车几何（mesh 碰撞体 + 真轮尺寸）

## Goal

让 MuJoCo 的接触几何来自用户导入的真车模型 `装配.glb`（SolidWorks 导出，41 件），而不是当前的"长方体车体 + 4 个圆柱轮 + 一块薄铲板"。目标行为：**登台时车尾的"后铲"结构先搭上台沿、再靠真车轮距/轮径完成爬升**——即用户在桌面上要求的"用车屁股后面的结构上台"。

用户决策（2026-09-28）：关键结构件粒度（后铲 + 底板/上板主体）；**四个驱动轮也换成模型实测尺寸**（r=0.0325 m、轮距 0.229、轴距 0.150）；接受既有 MuJoCo replay 与 RL checkpoint 身份失效。

> **轮径更正（2026-09-28，本任务实验后）**：本文早期记录的 `r=0.046/0.043` 与"四轮直径 0.0918/0.0845/0.0812 不一致"**是错误数据**。根因是 `tmp/inspect_glb.py` 的"局部 AABB 八角点旋转法"：对带旋转的节点，把轴对齐包围盒的 8 个角点旋转后再求包围盒，等价于取外接球，随轮胎自转相位假膨胀。独立复核（自写 glTF 解析）+ 主代理复核（节点世界矩阵列范数）双重复算：glb 内**非单位缩放 0 个、非单位四元数 0 个**，四轮世界尺寸 = mesh 局部尺寸 = **直径 0.0650 m（r=0.0325）**、宽 0.029 m，四轮完全一致。落地的 `src/Sim.Mujoco` v2 与 `scenarios/wushu-ring-2026-mujoco-v2.json` 均按 r=0.0325 实现。

## 背景事实（来自 glb 解析，tmp/inspect_glb.py）

| 部件 | 模型实测（Y-up、车头 −Z、原点在轮轴平面） |
| --- | --- |
| 后铲 | 0.19 宽 × 0.078 深 × 0.053 高，车尾 Z=+0.13，下缘离地 ≈0.033 |
| 底板 / 上板 | 0.24 × 0.22，板顶 ≈ +0.026 |
| 轮胎 ×4 | **r=0.0325**（直径 0.0650）、宽 0.029，轮心左右 ±0.113/±0.116、前后 ±0.073/±0.077（轮距 0.229、轴距 0.150；四轮几何相同） |
| 铲臂 ×2 | 0.091×0.105×0.133，X=±0.077、Z=−0.11（车头侧） |
| 总规模 | 60,406 三角面 / 85,740 顶点 |

当前 MuJoCo 物理：车体 box 0.26×0.26×0.09（半宽 0.13）、轮 r=0.065 宽 0.03、轮距/轴距 0.18/0.16、仅一块前伸薄铲板；`WheelForceLimit=3.0 N/轮`。

坐标映射（已验证手性 det=+1）：`bodyX = −modelZ`（车头 → 车体 +X 前进方向）、`bodyY = −modelX`、`bodyZ = modelY`。

## Requirements

- R1 **几何来源**：物理车体由模型关键件生成——后铲与底板/上板各做一个凸体 geom；四个驱动轮用模型实测尺寸与位置（r=0.0325、轮距 0.229、轴距 0.150）。**不引入整车主体的单一凸包**（凸包会填平后铲与车体之间的凹角，使后铲失去勾沿几何）。
- R2 **资产入库**：网格资产必须进仓库（`src/Sim.Mujoco/assets/`），不得依赖 `C:/Users/Neco/Downloads/装配.glb` 这类本机路径；`MujocoModel` 生成时把资产 SHA-256 并入 `ModelSha256`（否则"换网格不改哈希"是身份漏洞）。
- R3 **资产加载**：MJCF 通过 MuJoCo 内存 VFS（`mj_defaultVFS` + `mju_addBufferToVFS`）引用 mesh，避免磁盘绝对路径进入 XML（绝对路径会破坏跨机哈希稳定性）。
- R4 **场景版本**：新增 `scenarios/wushu-ring-2026-mujoco-v2.json`（`modelVersion: wushu-mjcf-v2` + 真车 `vehicles` 参数）；`wushu-ring-2026-mujoco.json`（v1）保留原样，使既有 v1 replay 仍可通过身份校验。`PhysicsSpec` 增加 v2 常量并校验。
- R5 **登台可行性**：6 cm 台沿 > 真轮半径 4.6 cm，登台是首要风险。必须实验量化（后铲是否接触台沿、是否爬得上去、需不需要调整倒角/力矩/伺服）；**任何场地或力矩调整都必须作为显式决策记录**（含数值证据），不得静默调参。
- R6 **性能与吞吐**：几何变复杂后测单 tick 耗时与训练 reset 耗时，与 v1 对比并在报告中披露（对照 `TrainingResetPerformanceTests` 的门）。
- R7 **测试与身份**：Sim.Tests 全量通过（MuJoCo 相关用例的预期值按新物理更新）；v1 replay `replay-check`/parity 仍逐位通过；新物理下导出 v2 replay 并跑通校验。
- R8 **既有产物影响说明**：明确列出作废范围（MuJoCo replay、RL checkpoint、评测记录）与后续动作（重训、重评、冻结协议重新走）。
