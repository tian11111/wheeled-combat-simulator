# 小车设置界面与真车电机参数建模 — 实施报告（2026-09-29）

## 结论

按用户指正"整车质量漏算电池/电机/主控、车过轻被顶飞"完成两件事：①**质量与电机真值建模**（3.5kg + 博创尚和 2342 开环电机）；②**设置面板"小车"页**（质量/转速/扭矩/轮径可填，默认 2342 电机 + 3.5kg）。翻覆从 136 次/11 场降到 11 次（-92%），QACC 归零，比赛 9/11 跑满全场。全量 421 通过。

## 实施清单

1. **场景**（`scenarios/wushu-ring-2026-mujoco-v2.json`）：mass 3.5、maxSpeed 0.408、MOUNT_SPEED 500（≤极速）。
2. **Fsm.TimeScale**（`src/Sim.Core/Fsm.cs`）：行走类时限（登台/恢复/追块，11 处）按 参考极速1.5/当前极速 缩放——真车低速下恢复不再因时限过短失败；legacy（1.5）缩放恒 1，**行为逐位不变**。
3. **配重修正**（`MujocoModel.cs`）：配重封顶 `min(0.9, chassisMass×0.7)`（防轻车负质量）；配重入 **组 3** 且 `ProbeRay3D` 的 mj_ray 组掩码改为 0-2（配重物理不可碰、传感器不可见）。
4. **设置界面**（`godot/src/`）：`DesktopSettings.Vehicle` 段（质量/转速/扭矩/轮径，极速派生 `JsonIgnore`）；`ApplyVehicleOverrides` 仅作用于 v2 场景；`SettingsPanel` 第 4 页"小车"（四字段 + 派生极速/默认电机说明实时刷新）；`Main.cs` 三处场景构建链式应用。

## 验证

- **行为**（11 seeds v2 场景）：翻覆 11（-92%）、QACC 0、超限提前结束 2/11、比分正常。
- **测试**：全量 421 通过（+3 新用例：VehicleSettings 默认值/极值校验/应用范围 v1+legacy 不触碰）；v1 ModelSha256 与全部 legacy 断言维持不变。
- **桌面**：设置面板构建零 ERROR，`core=sim-core-1.0.4` Live 运行；"小车"页四字段默认值 = 2342 + 3.5kg。

## 披露

- **扭矩字段当前仅存档**：v2 执行器是速度伺服（ctrlrange=轮速上限），扭矩暂无直接作用点；后续力矩级建模（如爬坡扭矩限制）可直接消费该字段。
- **参数矩阵记录**：质量（1/2.5/3.5/4.5）、登台速度（400/550/780）、轮摩擦（1.0/1.5）、配重（0.35/0.55/前移）单变量实验数据在 `tmp/match-v2-*-10s.txt`；结论：质量是一阶因素，其余各轴 ±30% 摆动。
- **残余**：单次登台尝试仍有翻覆（11 次/11 场集中在倒车爬坡的 wheelie）；Fsm 爬坡姿态控制/坡道几何为后续方向（见 09-29-sensor-glb-3d report 追加节）。
